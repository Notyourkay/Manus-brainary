## 1. H1：安装、构建、启动

在仓库终端执行：

```bash
cd /Users/notyourkay/Manus-brainary
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm package
/Users/notyourkay/brainary-rc-0.2.0/bin/brainary -m gpt-5.5
```

在 TUI 输入：

```text
/poa fg /Users/notyourkay/Manus-brainary/dist/manus.poa
```

预期：检查和构建成功；显示自由文本任务输入框。TUI 宿主选择 `gpt-5.5`，以启用当前 SDK 对应的 V1 Agent 工具；程序创建的实际 Agent 使用 `custom / gpt-5.6-sol`，密钥通过既有配置提供。此处是 rc 版本的已验证启动配置，不修改用户的全局默认模型。

## 2. H2：自然语言生成与执行

提交以下任务：

```text
请把下面的会议记录整理为中文行动清单，并指出未明确的信息。只使用给出的事实，不要补充日期或负责人。
会议记录：张敏负责整理接口清单，周三前完成；李雷负责联调，等接口清单完成后启动；测试负责人和截止时间都还没确定。
输出要求：用 Markdown 表格列出事项、负责人、时间、依赖；表格包含接口清单、联调、测试三项；再用列表列出待确认项。先提取事实，再形成最终结果。
```

检查：

1. TUI 展示任务、生成的角色和执行步骤。
2. 资产中可查看每个 Agent 的系统提示词、上下文和工具配置。
3. 步骤包含执行指令、前置结果引用和验收条件。
4. TUI 展示步骤开始、检查结果、最终答案和保存路径。
5. 使用自己的另一条文本任务重新启动 Manus，确认得到对应方案与结果。

预期：流程完成，方案实际参与执行。无需固定生成两个 Agent；角色和实例数量可由方案决定。

## 3. H3：结果正确性与失败语义

对样例逐项核对：

| 检查项 | 预期 |
| --- | --- |
| 接口清单 | 张敏负责，周三前完成 |
| 联调 | 李雷负责，依赖接口清单完成；未自行补充完成日期 |
| 测试 | 负责人和截止时间均标记未明确 |
| 格式 | 包含事项、负责人、时间、依赖的 Markdown 表格及待确认项 |
| 事实 | 未新增原文不存在的人员、日期和任务承诺 |

失败控制的确定性检查：执行 `pnpm test -- tests/execution.test.ts`，查看“failed revision”和“stop without revision”用例通过。它们验证真实执行器在检查失败后停止下游，不代表模型必定在某个自然语言样例上失败。

真实模型产生修订时，打开轨迹检查修订反馈、前次输出及下一次尝试的关系；没有修订的成功任务不要求人为制造一次修订。

## 4. H4：检查资产与留痕

使用 TUI 输出的绝对路径打开资产目录与运行目录。约定目录位于启动工作目录的 `artifacts/manus/` 下。

| 文件 | 内容 | 核查方法 |
| --- | --- | --- |
| `task.poa` | 可独立执行的任务包 | 文件存在，可在新会话启动 |
| `asset.json` | 原任务、Agent 定义、执行方案、模型/版本、资产 ID | 内容与 TUI 一致 |
| `record.json` | 本次运行信息、状态、结果与资产关联 | run ID 与 asset ID 可区分 |
| `trace.jsonl` | 按时间顺序记录生成、调用、检查、修订、失败/完成 | 实例 ID、输入输出、步骤关联完整 |
| `result.md` | 最终任务结果 | 按 H3 对照 |
| `wm-snapshot.json` | SDK 读回的运行状态快照 | 能对应本次运行的状态与标识 |

可执行以下命令核查记录关联、WM 快照一致性、调用数量和结果一致性：

```bash
node scripts/check-run.mjs <运行目录>
node scripts/check-run.mjs <复用运行目录> <原生成运行目录>
```

预期输出 `verified: true`；复用运行的 `generatorCalls` 必须为 0。该命令核对运行证据，任务内容正确性仍按 H3 检查。

关闭 TUI 后重新打开上述文件，内容仍存在。生成失败也应保留已接收的任务、生成原文或错误、已发生的轨迹，不输出假的成功结果。

## 5. H5：独立重跑生成的任务包

1. 复制 TUI 输出的任务包绝对路径。
2. 退出原会话，用 `brainary -m gpt-5.5` 打开一个新的 Brainary TUI。
3. 输入 `/poa fg <任务包的绝对路径>`。
4. 不重新输入原任务、不重新生成方案，观察任务开始执行。
5. 对比原运行和复用运行的记录。

预期：

- 资产 ID、任务、Agent 定义与方案保持一致。
- 复用运行出现新的 run ID 和真实任务 Agent 实例 ID。
- 轨迹没有生成 Agent 调用；任务步骤正常执行并产出结果。
- 新运行单独保存记录，原运行证据保留。
- 任务包包含运行程序与定义，不依赖 Manus 源码或其 `node_modules`。运行机器仍需要 Brainary、模型配置，以及本阶段用于输出文件的 Node.js。

可以把 `task.poa` 复制到另一个工作目录后启动，进一步核对资产独立性。第一版独立复用指执行已经保存的原任务；同类新任务的参数化不属于本次验收。
