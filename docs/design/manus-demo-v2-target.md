# Manus V2 目标架构

日期：2026-11-12。性质：基于 V1 现状和原工程报告的设计建议，用于对齐最终 Demo；V2 尚未开始开发。

## 1. 目标

保留自然语言输入、Agent 与方案生成、任务包交付和独立复用，在 V1 已补充的领域资料、经历查询与人工经验读取基础上，增加自动经验提炼和内外层 RSI。改进需要形成可使用的新版本，并用相同验收集证明收益。

V1 已包含自然语言任务理解、工具执行与基础记忆读取，现状以 `manus-demo-v1.md` 为准。

## 2. 生成与执行主线

1. TUI 接收任务，Manus PoA 组织上下文准备。
2. 按任务选择领域概念、关系、规则、技能资料，以及相关经历和已验证经验；保留来源及版本。
3. Manus PoA 调用生成 Agent，得到 Agent 定义与执行方案，在应用入口校验。
4. Manus 组合执行程序、定义、方案、所选上下文与版本，导出完整 task.poa。
5. 初次执行或独立任务包通过同一执行器创建任务 Agent，传递依赖结果，检查并按方案修订。
6. 保存当前状态、结果和轨迹，归档为一次运行经历。

PoA 负责控制和数据传递；Agent 实例执行模型任务；Agent 定义属于可版本化数据。生成 Agent 返回内容，Manus 程序完成打包和文件操作。

## 3. 记忆分工

| 内容 | 最小内容 | 读取时机 | 验收点 |
| --- | --- | --- | --- |
| 领域本体 / 技能资料 | 概念、关系、业务约束、解法与来源 | 生成前按领域选择 | 输入未直接给出的已提供领域规则，能进入生成上下文并影响方案 |
| WM 工作记忆 | 当前目标、步骤状态、结果与检查结论 | 本次运行中 | 状态与实际执行一致，调用正式 SDK 保存/读回 |
| Episodic memory | 任务、配置版本、操作序列、结果、错误、摘要 | 相似任务准备和复盘时 | 能按任务特征找到过去运行，返回证据与 run ID |
| 长期经验 | 经验内容、适用条件、来源经历、评价依据与版本 | 生成或执行前 | 新任务能读取适用经验，记录实际使用了哪一版 |

静态领域资料与历史记录读取不依赖 RSI 才能成立。经验可以先由人工维护，自动提炼与更新再接入 RSI。正式存储和检索按 SDK 提供的能力使用；缺少必要接口时给负责人反馈。应用侧文件可作为明确的 Demo 数据载体，不自建通用记忆框架。

## 4. 内外层 RSI

| 改进对象 | 候选内容 | 应用位置 |
| --- | --- | --- |
| 内层：任务执行 | Agent 定义、任务知识、指令、步骤、依赖与检查条件 | 新版本任务资产及 task.poa |
| 外层：生成方法 | 生成提示、规则、模板选择和默认要求 | Manus 下一次生成时采用的生成策略版本 |

闭环：经历与反馈 → 复盘 → 候选改进 → 基线/候选对照 → 采用有效版本或保留基线 → 后续调用。

先在固定任务集、相同模型与资源条件下比较质量、失败情况、耗时和调用量。内层候选验证执行效果；外层候选还需在同类新任务上验证生成效果。记录各次配置、执行结果和选择依据，避免把一次模型自评当作已证实的改进。

目标图合并展示复盘与评估能力，具体实现可以复用同一套执行和记录模块。无需因为“内外层”新增两套基础框架。

## 5. 资产复用与版本

当前 task.poa 已分离任务方法与材料，默认直接重跑包内原请求/快照，显式传入新请求时处理同类新任务。V2 保留此契约，新增版本继承关系：parent asset、采用的生成策略/知识版本、来源经历、评估结果及选择结论。

已归档任务包保持所选上下文与方案。V1 已通过自然语言入口接收同类新任务，并通过外部经验文件读取本次经验、保存来源。V2 延续此入口策略，不能静默修改已归档定义和方案。内层改进输出新任务包，外层改进输出新生成策略，旧版本与证据保留。

## 6. 能力归属与交付

模板提供工程与打包流程；PoA SDK 提供调用接口；WM SDK/Runtime 负责通用状态、快照与记忆能力；Manus 定义应用数据、选择上下文、生成与执行、复盘与评估。

当前 `wm-snapshot.json` 是 read_data 的本地导出。正式快照接入时适配 SDK 的存储/恢复契约，业务字段仍由 Manus 设计。

V2 验收应同时展示：领域规则实际参与、历史经历被召回、经验被后续任务使用、内层产出有效新任务包、外层产出有效新生成策略，以及完整的基线/候选比较证据。具体场景与度量在进入实现计划时确定。
